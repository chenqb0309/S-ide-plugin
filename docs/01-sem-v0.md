# `.sem` v0 文法（子集）

`.sem` 是**契約語言**，不是自然語言散文。

> **原則：骨架精確，body 自由。**
> 契約（名稱、型別、連結）必須精確；實作描述可以是很自然的工程中文。

這份文法同時被三個地方消費，所以它是三者的唯一真相：

1. **TextMate grammar** — 關鍵字高亮
2. **parser** — 抽簽章與依賴，算 cache key、解析連結
3. **AI System Prompt** — 穩定文法才可能下穩定約束

---

## 定址規則（v0 的關鍵約定）

連結、快取失效、依賴圖三件事都要**唯一定址**。因此 v0 立下三條硬約定：

| # | 約定 | 為什麼 |
|---|---|---|
| 1 | **類別名全域唯一**（一個 workspace 內不可重複） | 讓 `類別.方法` 只靠 regex 就能解析，不需語意分析 |
| 2 | **禁止多載**（不可同名不同參數） | 否則 `類別.方法` 無法唯一定址 |
| 3 | `unit key = 類別名.方法名` | 連結、cache key、manifest 共用同一個 key |

> 中文類別名本來就長、衝突機率低，所以「全域唯一」不會造成負擔，還讓連結短。
> **違反 1 或 2 時，harness 直接報錯（規格 lint），不進生成。** 這是免費拿到的第一層驗證。

## 類別

```sem
類別 出貨服務 {
    契約 {
        `運費計算器`
        `庫存服務`
        `稽核日誌`
    }

    方法 出貨 {
        輸入: 訂單 單
        輸出: 字串

        呼叫 `庫存服務.檢查庫存`，不足則返回「單號 庫存不足」
        ...
    }
}
```

`契約` 是**這個類別會用到的協作者清單**，每一行就是一個連結。

**它只宣告「需要什麼」，不寫「怎麼來」。** 欄位與實例由 harness 生成：

```csharp
public partial class 出貨服務
{
    private readonly 運費計算器 運費計算器 = new 運費計算器();
    private readonly 庫存服務   庫存服務 = new 庫存服務();
    private readonly 稽核日誌   稽核日誌 = new 稽核日誌();
}
```

（欄位名 = 類別名。body 直接寫 `庫存服務.檢查庫存(單)`，**不要自己 `new`**。）

**這是 unit 邊界能成立的前提：AI 只能「使用」契約裡的東西，不能「發明」。**

> 這條規則是為了消滅一類修不好的錯誤。例：AI 自己寫出 `_db` 卻沒人宣告它 → `CS0103` → 迴圈重寫一百次 body 都修不好，因為 `_db` 是欄位，不在方法 body 裡。詳見 [02-prelude-v0.md](02-prelude-v0.md)。

> **`契約` 的內容會進 context map**，AI 看得見欄位名。這是免費的護欄。

## 資料（DTO）

```sem
資料 用戶 {
    字串 Email
    字串 密碼雜湊
}
```

`資料` 與 `契約` 形狀都是 `型別 名稱`，但語意相反：

| | 意思 | 生成 |
|---|---|---|
| `資料` | 它**是**什麼（值物件，會被傳遞／序列化） | `public class X { public T A { get; set; } }` |
| `契約` | 它**用**什麼（協作者，由 harness 注入） | `private readonly T name = new T();` |

## 方法

**上半是契約，下半是實作。**

```sem
方法 計算運費 {
    輸入: 訂單 單
    輸出: 小數

    步驟 "免運門檻"
    單 的總金額 達到 1000 元，運費為 0 並直接返回
    返回 運費
}
```

| 行 | 意義 | 可省略 |
|---|---|---|
| `輸入: 型別 名稱` | 參數（多個用逗號：`輸入: 箱規格 規格, 整數 高度`） | 是 → 無參數 |
| `輸出: 型別` | 回傳型別 | 是 → `空`（`void`） |

```sem
方法 主 {
    步驟 "建立樣本"
    ...
}
```

- **`輸入` / `輸出` 之後就是 body**，body 是自由散文——這就是「骨架精確，body 自由」的字面形狀
- **簽章是凍結契約**：改簽章 = 全專案失效事件（見 [S1](S1-incremental.md)）
- 舊寫法 `方法 名稱(型別 參數): 型別` **不會被解析**（方法會整條消失），lint 會當場報錯

## 語句（v0 子集）

| 語法 | 意義 | 生成 |
|---|---|---|
| `` `類別` `` `` `類別.方法` `` | **可跳轉的單元引用** | 方法呼叫 |
| `如果 條件 { }` | 條件分支 | `if` |
| `否則如果 條件 { }` | — | `else if` |
| `否則 { }` | — | `else` |
| `每個 X 於 集合 { }` | 走訪 | `foreach` |
| `重複 N 次 { }` | 固定次數 | `for` |
| `返回 值` | 回傳 | `return` |
| `拋出 錯誤(X)` | 丟例外 | `throw` |
| `嘗試 { } 捕捉 錯誤 { }` | 例外處理 | `try/catch` |
| `步驟 "說明"` | **業務時序鏈**的標記點 | `Telemetry.Step(...)` |

v0 **不做**：`當`（while，可後補）、集合字面值、字串插值、泛型方法的型別參數、`大於`/`小於` 以外的運算式語法。

**除了連結與 `步驟`，其餘都是自由散文。**

## 機制不住文件裡

v0 **沒有修飾符**。並行、鎖、可見性、資料存取這些機制，一律由 **harness 的規則**決定，不寫進 `.sem`。

判準：**這個標記，是在描述「要什麼」，還是在告訴機器「怎麼做」？**

| 想要的效果 | 舊寫法（已廢除） | 現在的寫法 |
|---|---|---|
| 同一時間只准一個人扣庫存 | `【獨佔鎖定】` | 不用寫——對 `契約` 的寫入由 harness 依規則序列化 |
| 回傳 `Task<T>` | `【非同步】` | 不用寫——簽章的返回型別已經表達了 |
| `internal` 可見性 | `【僅內部】` | 不用寫——由架構層決定 |
| 這幾步可以同時跑 | `【並行處理】` | 不用寫——v0 一律循序（**保守＝安全**） |

> **每次想加語法，先問：這個機制能不能由 harness 依意圖推斷？能，就不要寫。**
>
> 這條原則同時產生兩個決定：連結用**維基式反引號**、**修飾符全部廢除**。

## 連結語法

**反引號：`` `類別` `` 或 `` `類別.方法` ``。**

選反引號而不是 `[[...]]`，因為程式設計師對「反引號 = 識別字」已經有肌肉記憶，寫在中文句子裡也讀得順：

```sem
呼叫 `庫存服務.檢查庫存`，不足則返回「單號 庫存不足」
```

它是**維基連結**，不是函式呼叫——所以**不帶參數**。參數用敘述寫：

| 像程式（不要） | 像規格（要這樣） |
|---|---|
| `` `庫存.扣減(數量)` `` | 從 `庫存` 扣掉 數量 |

- `DocumentLinkProvider` 渲染為可點擊連結
- `Ctrl + 點擊` 跨檔跳轉；`F12` 精確跳到目標行
- **指向不存在的目標 → 當場畫紅線**（`DiagnosticCollection`）

**這讓 `.sem` 不只是文字，而是一張有連結的圖。**

而且**斷鏈偵測是免費的規格 lint** ——在完全沒有底層程式碼的狀態下，靠純文字拓撲抓出規格層的錯誤。

> 連結**不會被靜默跳過**：任何解析不到的目標都報錯。連結是唯一的依賴宣告，靜默等於規格殘缺。
